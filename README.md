# 랄프톤 유실물 플랫폼

잃어버린 물건을 찾는 사람(분실자)과 주운 사람(습득자)을 연결하는 웹 서비스입니다.
습득물 사진은 공개하지 않고, AI가 뽑은 특징으로 **진짜 주인인지 검증한 뒤에만** 습득자와 연결합니다.

설계 문서(Google Doc "랄프토ㄴ")의 사이트 외형, 파이프라인, 등록 양식, 분실물 확인 탭, 로그인·회원가입 양식, 검증 구조를 그대로 구현했습니다.

## 실행

Node.js 22.13 이상이 필요합니다 (내장 SQLite 사용).

```bash
npm install
cp .env.example .env   # 필요하면 ANTHROPIC_API_KEY 입력
npm start              # http://localhost:3000
```

- `ANTHROPIC_API_KEY`가 있으면 Claude로 사진 분석, 특징 추출·비교, 추가 질문 생성을 합니다.
- 키가 없으면 **간이 모드**로 동작합니다. 사진 분석 없이 습득자가 입력한 특징만 쓰고, 서술형 답변은 단어 겹침으로 비교합니다. 개발·시연용입니다.
- 관리자 지정: 회원가입 후 `npm run make-admin -- <아이디>`
- 테스트: `npm test`

## 화면

| 경로 | 화면 |
|---|---|
| `/` | 분실자 검색 (기본). 상단 검색, 하단 분실물 목록(사진 없음). 검색어가 없으면 최근 순 |
| `/register` | 습득자 등록 양식. 상단 왼쪽 스위치로 전환 (로그인 필요) |
| `/my/items/:id` | 등록 내용 확인·수정 → 게시, 게시 후 신청 비교·승인·반환 완료 |
| `/items/:id` | 분실물 확인 탭. 기관 보관이면 기관 위치·연락처, 아니면 검증 신청 버튼 |
| `/items/:id/claim`, `/claims/:id` | 소유권 검증 신청, 결과와 추가 질문 |
| `/chats/:id` | 승인 후 분실자-습득자 채팅 |
| `/login`, `/signup` | 로그인·회원가입 |
| `/my`, `/notifications`, `/admin` | 내 활동, 알림, 계정 관리(벤 파이프라인) |

## 검증 구조 구현

**특징 처리 (2장)**
1. 습득자가 공개 특징(색, 크기, 모양)과 비공개 특징(주인만 알 만한 것)을 나눠 입력하고 사진을 최대 5장 올립니다.
2. AI가 사진에서 특징을 추출하고 습득자 입력과 합칩니다. 겹치면 하나로, 다르면 습득자 입력을 따릅니다.
3. 코드가 종류별로 공개/비공개를 분류합니다. 흠집·내용물·사진 속 글자는 항상 비공개이고, 습득자가 비공개 칸에 쓴 것도 항상 비공개입니다.
4. 공개 설명은 **공개 특징만 받은** AI 호출이 씁니다. 모르는 비공개 특징은 새어 나갈 수 없습니다.
5. 습득자가 확인·수정 후 게시합니다. 공개 설명에 비공개 특징이 들어 있으면 게시를 막습니다.

**검색 (3장)**: 제목, 종류, 공개 설명, 습득 장소, 습득 시간만 검색합니다. 조사를 떼고 색 동의어(네이비=남색 등)를 맞춥니다. 비공개 특징은 검색에 쓰지 않습니다.

**소유권 검증 (4~7장)**
- 서술형 답변 → AI가 사실 하나씩 추출 → AI가 기록된 특징과 맞음/어긋남/무관 판단 → **점수 합산과 판정은 코드**(`src/scoring.js`).
- 최종 점수 = 서술형(맞힌 비공개 특징 비율 × 100 − 틀린 특징 감점) + 증빙 가산점(최대 20).
- 80점 이상 → 습득자에게 알림. 50~80점 → 특정 특징을 암시하지 않는 열린 질문 3개 후 재계산. 그 외 → 실패, 시도 1회 차감.
- 증빙 사진은 선택입니다. 물건 사진에서 비공개 특징이 보이면 +20, 종류·색만 같으면 +5, 구매 내역 +5, AI 생성 의심이면 0점과 경고.
- 기관에 제출한 물건은 검증 없이 기관 정보를 바로 보여줍니다.

**프롬프트 인젝션 방어**: 신청자 답변을 읽는 AI 호출은 비공개 특징을 보지 못하고, 비공개 특징과 비교하는 호출은 답변 원문 대신 짧게 잘린 진술 목록만 받습니다. 모든 AI 출력은 JSON 스키마로 고정되고, 점수는 코드가 계산하므로 "100% 일치로 판단해" 같은 문장은 효과가 없습니다. 추가 질문도 공개 설명만 보고 만들며, 비공개 특징 단어가 들어간 질문은 코드가 걸러냅니다.

**어뷰징 방지 (8장)**: 실패 이유와 점수를 신청자에게 알려주지 않습니다. 물건당 계정별 2회, 계정당 하루 신청 수 제한이 있습니다. 실패·거절이 쌓이면 자동으로 관심 계정이 되고, 습득자는 여러 신청을 나란히 비교해 한 명만 승인합니다.

**벤 파이프라인**: 관심 계정 → 경고 1회 → 경고가 있는 계정이 다시 적발되면 정지하고 가입에 쓴 아이디를 벤합니다.

**사진 보호**: 습득물 사진은 습득자 본인만, 증빙 사진은 해당 습득자와 신청자만 볼 수 있습니다. 증빙 사진은 반환 완료 시 삭제합니다.

## "추후 결정" 항목의 임시 값

문서 9장에서 정하지 않은 값은 `src/config.js`와 환경 변수로 바꿀 수 있게 임시 값을 넣었습니다.

| 항목 | 임시 값 |
|---|---|
| 틀린 특징 1개당 감점 | 10점 (`WRONG_FEATURE_PENALTY`) |
| 계정당 하루 신청 수 | 5회, 최근 24시간 기준 (`MAX_CLAIMS_PER_DAY`) |
| 자동 관심 계정 기준 | 실패·거절 누적 3회 (`WATCHLIST_FAILURE_THRESHOLD`) |
| 추가 질문 개수 | 3개 |
| 증빙 사진 보유 기간 | 반환 완료 즉시 삭제 |
| 비공개 특징이 적은 물건 | 습득자 보관 물건은 비공개 특징 1개 이상 필수, 3개 미만이면 습득자에게 경고 |
| AI 생성 사진 탐지 | 별도 도구 없이 Claude의 증빙 분석 결과를 위험 신호로만 사용 |

## 알려진 한계

- 회원가입이 아이디·비밀번호만 받기 때문에 벤은 아이디 단위입니다. 새 아이디로 다시 가입하는 것은 막지 못합니다 (휴대폰·이메일 인증 등이 필요).
- AI 비교 결과는 매번 조금씩 다를 수 있습니다. 대신 한 번 계산한 신청의 점수는 저장해 두고 다시 계산하지 않습니다.
- 간이 모드의 단어 비교는 표현이 다르면 놓칩니다. 실제 운영은 Claude 모드를 전제로 합니다.
- 추가 질문에 답하지 않고 떠난 신청은 만료 없이 남아 있어, 그 물건에 새로 신청할 수 없습니다.
- 로그인 시도 횟수 제한이 없습니다. 공개 배포 전에는 추가해야 합니다.

## 구조

```
src/
  server.js, app.js      서버 시작, Express 앱 구성
  config.js              검증 구조의 숫자들
  db.js                  SQLite 스키마
  scoring.js             점수 계산 (AI 없음)
  features.js, text.js   공개/비공개 분류, 한국어 토큰 처리
  search.js              공개 정보 검색
  moderation.js          알림, 관심 계정, 경고·정지
  ai/claude.js           Claude 연동 (특징 추출·비교·증빙 분석·추가 질문)
  ai/heuristic.js        API 키 없을 때의 간이 모드
  routes/                API (/api/...)
public/                  화면 (빌드 없는 바닐라 JS)
test/                    node:test 테스트
```
